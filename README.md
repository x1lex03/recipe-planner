
# 🍽️ Платформа для рецептов и планирования питания на Node.js с Redis

Курсовой проект по дисциплине «Современные платформы программирования».

Веб-платформа для хранения рецептов, планирования питания на неделю и автоматического формирования списка покупок. Серверная часть разрабатывается на Node.js с использованием Express.js, а Redis используется в качестве основной NoSQL-базы данных.

---

## 📌 О проекте

Цель работы — разработать веб-платформу для создания и хранения рецептов, составления недельного плана питания и автоматического формирования списка покупок с использованием Redis в качестве основной базы данных.

### Задачи проекта

1. Изучить возможности Node.js, Express.js и Redis для разработки веб-приложений.
2. Проанализировать предметную область и определить функциональные требования к платформе.
3. Спроектировать архитектуру приложения и структуру хранения данных в Redis.
4. Реализовать регистрацию пользователей и разграничение их данных.
5. Разработать функциональность создания, просмотра и редактирования рецептов.
6. Реализовать составление недельного плана питания.
7. Разработать алгоритм автоматического объединения ингредиентов и формирования списка покупок.
8. Провести тестирование и отладку основных сценариев работы приложения.

### Актуальность

Планирование питания позволяет систематизировать рацион, заранее определять необходимые продукты и упрощать процесс приготовления блюд.

Использование Redis позволяет организовать хранение данных в структурах, подходящих для работы с рецептами, пользовательскими данными и планами питания. Это делает Redis подходящим инструментом для разработки данной платформы.

## 🏗️ Архитектура системы

Платформа разрабатывается по клиент-серверной архитектуре.

Основные компоненты:

- Клиентская часть — интерфейс для взаимодействия пользователя с платформой.
- Серверная часть — обработка HTTP-запросов, проверка данных и выполнение бизнес-логики.
- База данных Redis — хранение пользователей, рецептов, ингредиентов и планов питания.

Взаимодействие компонентов:

1. Пользователь выполняет действие в интерфейсе.
2. Клиент отправляет HTTP-запрос на сервер.
3. Сервер проверяет входные данные и выполняет необходимую операцию.
4. При необходимости сервер обращается к Redis.
5. Результат возвращается клиенту.

## 🗄️ Структура данных Redis

Для хранения данных предполагается использование следующих структур Redis:

| Структура | Назначение |
|---|---|
| Hash | Хранение отдельных полей пользовательских данных |
| Set | Хранение уникальных идентификаторов и связей |
| Sorted Set | Хранение упорядоченных элементов, если требуется сортировка |
| JSON | Хранение рецептов и сложных структурированных объектов |

### Основные сущности

**User** — пользователь платформы.

Содержит идентификатор, данные для авторизации и другую необходимую информацию.

**Recipe** — рецепт блюда.

Содержит название, описание, ингредиенты, их количество, единицы измерения и шаги приготовления.

**Ingredient** — ингредиент.

Содержит название продукта, количество и единицу измерения.

**MealPlan** — план питания.

Содержит пользователя, период планирования и перечень блюд, распределённых по дням недели.

**ShoppingList** — список покупок.

Формируется на основе ингредиентов выбранных рецептов и плана питания.

## ⚙️ Основной функционал

### 1. Работа с пользователями

- Регистрация и авторизация.
- Разграничение данных пользователей.
- Хранение пользовательских данных в Redis.

### 2. Работа с рецептами

- Создание новых рецептов.
- Просмотр сохранённых рецептов.
- Редактирование рецептов.
- Добавление ингредиентов и шагов приготовления.

### 3. Планирование питания

- Составление плана питания на неделю.
- Добавление рецептов в определённые дни.
- Просмотр и редактирование недельного плана.

### 4. Формирование списка покупок

- Автоматическое получение ингредиентов из плана питания.
- Объединение одинаковых ингредиентов.
- Суммирование количества продуктов с одинаковыми единицами измерения.
- Формирование общего списка покупок.
